Architecture

Large Language Models

The transformer architecture that underpins every major LLM — the self-attention mechanism in full mathematical detail, positional encoding, scaling effects, and the alignment stack that makes models safe to deploy.

From RNNs to Transformers

In plain terms

Before 2017, a language model read a sentence the way you do — one word at a time, carrying a summary of everything so far in its head. That summary kept getting blurrier, so anything said fifty words ago was effectively forgotten, and because each word had to wait for the one before it, training could not be parallelised. The transformer's insight was to abandon reading in order entirely: let every word look directly at every other word, all at once. Distance stops mattering, and the whole thing runs in parallel on a GPU.

Prior to 2017, language models used Recurrent Neural Networks (RNNs). An RNN processes tokens sequentially, maintaining a hidden state hₜ:

h_t = tanh(W_h h_{t-1} + W_x x_t + b) [RNN cell]

The problem: this sequential computation is inherently serial — you cannot compute h₄₀ before h₃₉. Training is slow. Worse, gradients must flow backwards through hundreds of time steps — they vanish. Long-range dependencies (a pronoun referring to a subject 500 words earlier) are essentially unlearnable.

The Transformer (Vaswani et al., "Attention Is All You Need", 2017) eliminated recurrence entirely. Every position in a sequence attends to every other position simultaneously via the self-attention mechanism. Training is fully parallelisable. Long-range dependencies are modelled in a single attention step regardless of distance.

Scaled Dot-Product Attention

The core operation of a transformer. Given a sequence of token representations packed into a matrix X ∈ ℝ^{n×d} (n tokens, d dimensions), three linear projections produce Query, Key, and Value matrices:

Q = X W_Q W_Q ∈ ℝ^{d × d_k} K = X W_K W_K ∈ ℝ^{d × d_k} V = X W_V W_V ∈ ℝ^{d × d_v} Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V Dimensions: QKᵀ ∈ ℝ^{n × n} (n²-size attention matrix — cost at long contexts) √d_k scales raw dot products to prevent softmax saturation at large d_k softmax row-wise → each row sums to 1 (weights over values) Output ∈ ℝ^{n × d_v}

Intuition: Q encodes "what I'm looking for," K encodes "what I contain," and V encodes "what I contribute." The dot product QKᵀ scores how relevant each key is to each query. Softmax normalises into weights. The output is a weighted sum of values — each token's new representation is an attention-weighted blend of all other tokens' value projections.

Why divide by √d_k ? With large d_k (e.g. 128), dot products QᵢKⱼ have variance proportional to d_k. Without scaling, these large values push softmax into near-zero gradient regions — the largest logit dominates with probability ≈1, all others ≈0, and gradients vanish. Dividing by √d_k keeps dot product variance constant at 1 regardless of d_k.

Causal Masking

During training (and in decoder-only models like GPT/LLaMA/Claude), each token may only attend to previous tokens — not future ones. This is implemented by adding −∞ to the upper triangle of QKᵀ before softmax, so e^{−∞} = 0 after softmax:

Masked_Score(i,j) = QᵢKⱼᵀ / √d_k if j ≤ i = −∞ if j > i After softmax, future positions receive attention weight 0.

Multi-Head Attention

A single attention head can only model one type of relationship at a time. Multi-head attention runs H independent attention operations in parallel, each with its own projection matrices, then concatenates and projects results:

head_h = Attention(Q W_Q^h, K W_K^h, V W_V^h) for h = 1, …, H W_Q^h ∈ ℝ^{d × d_k} where d_k = d/H (split model dimension across heads) W_K^h ∈ ℝ^{d × d_k} W_V^h ∈ ℝ^{d × d_v} where d_v = d/H MultiHead(Q,K,V) = Concat(head₁, …, head_H) · W_O W_O ∈ ℝ^{Hd_v × d} (output projection combining all heads) Example (LLaMA-3 70B): d=8192, H=64, d_k=d_v=128 Total parameters in MHA: 4d² = 4×8192² = 268M per layer

Different heads empirically specialise: some track syntactic dependencies, others co-reference, others domain-specific patterns. Head 3 in layer 15 of a large LLM might specialise in tracking which entity a pronoun refers to 200 tokens back.

Grouped Query Attention (GQA)

Standard MHA replicates K and V matrices for every head — expensive for KV cache. Grouped Query Attention (Ainslie et al., 2023, used in LLaMA-3, Mistral) groups Q heads and shares a single K, V per group:

G groups, H query heads, H/G key-value heads. KV cache size reduction: H/G × smaller (G=8 → 8× smaller KV cache) Quality impact: minimal — KV sharing loses little information at scale LLaMA-3 70B: H=64 query heads, G=8 groups → 8 KV heads KV cache reduced from 64× to 8× (8× memory saving for long contexts)

The Transformer Block

Each of the L transformer layers (blocks) applies two sub-layers in sequence, each followed by residual addition and layer normalisation:

x' = x + Attention(LN(x)) [multi-head self-attention + residual] x'' = x' + FFN(LN(x')) [feed-forward network + residual] LN = Layer Normalisation (pre-norm variant, used in modern LLMs) This is the "pre-norm" formulation; original 2017 transformer used post-norm.

Feed-Forward Network (FFN)

The FFN applies two linear projections with a nonlinearity in between. It constitutes ~2/3 of parameters in a transformer:

FFN(x) = W₂ · SiLU(W₁x) ⊙ (W₃x) [SwiGLU variant, used in LLaMA] W₁ ∈ ℝ^{4d × d}, W₂ ∈ ℝ^{d × 4d}, W₃ ∈ ℝ^{4d × d} Intermediate dim = 4d (or ≈2.67d for SwiGLU with same parameter count) FFN parameters per layer: 3 × d × 4d ≈ 12d² (SwiGLU has 3 weight matrices) Attention parameters per layer: 4d² Ratio: FFN ≈ 3× attention parameters

Positional Encoding

Self-attention is permutation-invariant — the same result regardless of token order. Positional encoding injects order information. Modern LLMs use Rotary Positional Embeddings (RoPE):

RoPE rotates the Query and Key vectors for position m by angle mθᵢ: Q_m = R(m) · Q where R(m) is a rotation matrix parameterised by position m K_n = R(n) · K After rotation: Q_m · K_nᵀ depends only on the relative position (m − n): Q_m · K_nᵀ = (R(m)Q) · (R(n)K)ᵀ = Q · R(m−n) · K Rotation angles: θᵢ = 1 / 10000^{2i/d} for dimension i Benefits: - Attention scores naturally decay with distance (cos(mθᵢ) behaviour) - Extrapolates to longer contexts than training (with YaRN or NTK scaling) - No learned parameters — mathematically principled

Scale and the Emergence of Capability

Model capability scales as a smooth power law with parameters, data, and compute — until it doesn't. Emergent abilities are qualitative capability jumps that appear discontinuously at specific scale thresholds, not predicted by interpolating from smaller models:

Parameter counts have stopped being a useful headline Three things broke the old comparison. Sparsity: a 671B-parameter MoE model activating 37B per token costs roughly what a 37B dense model costs to run, so "parameters" now needs the word "total" or "active" attached to mean anything. Non-disclosure: frontier labs largely stopped publishing architecture details, so the widely quoted figures for closed models are informed guesses. Inference-time compute: a smaller model that reasons for thirty seconds routinely beats a larger one that answers immediately, so capability no longer tracks size in any simple way. The honest modern description of a model is a triple — active parameters, training tokens, and reasoning budget — and even that omits the post-training, which may matter most of all.

Mixture of Experts (MoE)

MoE replaces each FFN with E independent expert networks. A learned router network selects the top-k experts (typically k=2) for each token:

Router: g(x) = TopK(softmax(W_r · x), k) scores each expert for token x MoE-FFN(x) = Σ_{i ∈ TopK} g(x)_i · Expert_i(x) Total parameters: E × FFN_params Active parameters per token: k × FFN_params (only k experts fire) Mixtral 8×7B: 8 experts, 2 active → 46.7B total params, 12.9B active per token → inference cost of a 13B model, quality approaching a 70B model
In plain terms

Instead of one enormous general-purpose layer that every word must pass through, an MoE layer is a room full of specialists with a receptionist at the door. Each word is sent to the two or three specialists most likely to be useful, and the rest of the room sits idle. The model can therefore know far more than it has to compute for any single word — which is why total parameter counts have grown so much faster than the cost of running them.

Mixture-of-experts has gone from a research curiosity to the default architecture for frontier models, and the design has sharpened considerably since Mixtral:

  • Far more, far smaller experts. Modern designs use hundreds of fine-grained experts rather than eight large ones, with a higher top-k. More specialisation, better load balance, and a smoother capability curve.
  • Shared experts. One or more experts every token passes through, capturing general knowledge, so the routed experts are free to specialise rather than each re-learning the basics.
  • Load balancing without auxiliary losses. Early MoE training needed an extra loss term to stop the router sending everything to a few favourite experts — which degraded quality. Bias-based balancing schemes achieve the same distribution without polluting the objective.
  • The real cost is memory, not compute. All experts must be resident even though few fire per token. A sparse model is cheap in FLOPs and expensive in HBM, which is precisely why the rack-scale NVLink domains described on the Hardware page were built.

Attention Variants That Shrink the KV Cache

Grouped-query attention was the first widely adopted response to KV cache pressure. Two further approaches now matter:

  • Multi-head latent attention (MLA). Rather than sharing key-value heads, compress keys and values into a low-rank latent vector, cache that, and reconstruct per-head projections on the fly. This can shrink the cache by an order of magnitude relative to standard multi-head attention while retaining more expressiveness than aggressive GQA — trading a little extra computation for a large memory saving, which is exactly the right trade when memory is the binding constraint.
  • Sparse and hybrid attention. Interleave full-attention layers with cheaper ones — sliding-window attention, or learned sparse selection of which past tokens to attend to. Some architectures go further and interleave transformer layers with state-space (Mamba-style) layers, which have constant memory per token rather than growing cache. These hybrids trade a small amount of recall for a large reduction in long-context serving cost.

Reasoning Models and Inference-Time Compute

In plain terms

For years, making a model better meant making it bigger and training it on more text. Then a third option appeared: let the model think for longer before answering. A model that writes out several thousand tokens of working — trying approaches, noticing errors, backtracking — before giving its answer can dramatically outperform the same model answering immediately. Thinking time became a resource you can buy, like parameters or data.

This is the most significant architectural shift since the transformer itself, and it is not an architectural change at all. The model is the same; what changed is the training that teaches it to use extra tokens productively, and the willingness to spend them at inference.

Three axes of scaling, and how they differ 1. Pretraining compute — more parameters, more tokens Paid once. Improves everything. Increasingly constrained by the supply of high-quality text. 2. Post-training compute — reinforcement learning on tasks with automatically checkable answers (maths, code, proofs) Paid once. Teaches the model to reason, persist, and self-correct. Scales with compute rather than with human labelling. 3. Inference-time compute — let the model generate a long chain of reasoning before committing to an answer Paid every single time you use it. Accuracy improves roughly log-linearly with reasoning tokens on hard problems, and not at all on easy ones. Axis 3 is qualitatively different: it turns capability into a per-query cost decision. You can now literally choose to buy a better answer.

How the capability is trained: the model is asked to produce a long chain of reasoning and then a final answer; the answer is checked by a program; trajectories leading to correct answers are reinforced. Crucially, nobody demonstrates how to reason — the reasoning behaviour emerges from the optimisation. Models trained this way spontaneously develop recognisable strategies: checking their work, trying an alternative approach after a dead end, and noticing their own errors mid-derivation. The same training recipe is what produces competent agents, which is why the Agentic AI page treats reasoning models as the unlock for practical agents.

Two cautions First, reasoning does not help uniformly. On problems with a verifiable structure — mathematics, competitive programming, logical deduction — the gains are dramatic. On open-ended writing, factual recall, or matters of taste, extra reasoning tokens mostly cost money. Deciding when to spend them is a real engineering problem, and it is why models increasingly expose a reasoning-effort control.

Second, the visible reasoning is not necessarily the actual computation. A model can reach an answer by one route and produce a plausible written derivation by another. Treat a chain of thought as generated text that correlates with the model's process, not as a log of it. This has direct consequences for oversight, discussed on the Safety & Governance page.

Context Length and Its Challenges

The attention matrix QKᵀ ∈ ℝ^{n×n} scales quadratically with sequence length n. Memory and compute cost of attention:

Attention memory: n² × n_heads × sizeof(float) per layer At n=128,000 tokens, H=64 heads, BF16: = (128,000)² × 64 × 2 bytes ≈ 2.1 TB per layer — clearly infeasible Solutions: FlashAttention: Tile attention computation to stay within L2/SRAM. Does not reduce asymptotic complexity but avoids writing n×n matrix to HBM. Memory complexity: O(n) instead of O(n²). Speeds up attention 2–4×. Sliding window attention (Mistral): each token attends to W=4096 recent tokens only. O(nW) complexity. Loses global context. Ring attention: distribute the n×n attention matrix across GPUs in a ring. Each GPU computes a local block; pass K,V between GPUs in a ring. Scales to 1M+ tokens by adding GPUs. Native sparse attention: learn which past tokens are worth attending to, rather than fixing the pattern in advance. Keeps a global receptive field at sub-quadratic cost, at the price of a harder training problem. Hybrid SSM layers: interleave transformer layers with state-space layers whose memory per token is constant. Long-context serving cost drops substantially; exact long-range recall degrades somewhat.
A long context window is not the same as using it well Retrieving a single fact planted in a million tokens — the "needle in a haystack" test — is close to solved and is a much easier problem than it sounds. Reasoning jointly over many facts spread across that same context is not, and measured performance degrades well before the advertised limit. This is the context rot discussed on the Agentic AI page, and it is why agent engineering is mostly about deciding what not to put in the window. Advertised context length is a capacity specification, not a capability claim.
FlashAttention implementation insight Standard attention materialises the full n×n attention score matrix to HBM (80 GB HBM at 3.35 TB/s). For n=32,768, this is 32,768² × 64 × 2 bytes ≈ 137 GB — far larger than HBM. FlashAttention-2 processes attention in tiles that fit in SRAM (20 MB on H100), never materialising the full matrix. The online softmax trick tracks the running normalisation across tiles without losing numerical stability.

Key takeaways

  • Attention replaced recurrence by letting every position look at every other position directly — which removes the distance penalty and makes training parallel.
  • Attention is O(n²) in sequence length. Nearly every architectural innovation since is an attempt to pay less for that without losing what it buys.
  • Grouped-query attention, multi-head latent attention and sparse or hybrid layers all target the same bottleneck: the KV cache, which dominates long-context serving cost.
  • Sparse mixture-of-experts is now the default frontier architecture. It decouples what a model knows from what it computes per token — cheap in FLOPs, expensive in memory.
  • Capability now scales along three axes: pretraining, post-training reinforcement learning, and inference-time reasoning. Only the third is paid per query.
  • A model's visible chain of thought correlates with its computation but does not faithfully report it.
