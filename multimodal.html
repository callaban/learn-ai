Foundations

Beyond Text

Diffusion, vision, video, audio, and world models. Language models get the attention, but the same transformer machinery — pointed at pixels and waveforms, and trained with a different objective — produces images, video and speech, and increasingly all of them in one model.

Prerequisites: Neural Networks, LLMs Reading time ~25 min Reviewed 2026

Everything Is Tokens

In plain terms

A transformer does not know what text is. It processes sequences of vectors. If you can turn something — an image, a second of audio, a video frame, a robot's joint angles — into a sequence of vectors, the same architecture works on it. That single observation is why one family of models now handles every kind of media.

The LLM page describes attention operating over token embeddings. Nothing in that mechanism is specific to language. The only question for a new modality is how to convert it into a sequence of vectors and back again.

Turning an image into a sequence A 224×224 RGB image = 150,528 numbers. One token per pixel would give a 50,176-token sequence per image — and attention is O(n²), so that is hopeless. Patch embedding (the Vision Transformer trick): 1. Cut the image into a grid of 16×16 pixel patches → 14×14 = 196 patches 2. Flatten each patch: 16 × 16 × 3 = 768 numbers 3. Project each through one learned linear layer → a d-dimensional vector 4. Add a positional embedding so the model knows where each patch was Result: 196 tokens, indistinguishable in form from 196 word tokens. The transformer proceeds exactly as before. Same idea elsewhere: audio → mel-spectrogram frames, or discrete codes from a neural codec video → spacetime patches (a patch across several adjacent frames) robots → joint angles and forces, projected to the same dimension
An analogy

A shipping container transformed global trade not by improving ships but by standardising the interface: anything that fits in a box can travel on any ship, crane or truck. Token embeddings are the container. Once every modality is packed into the same shaped box, one architecture — and one enormous investment in training infrastructure — serves all of them.

Connecting Vision to Language

Turning an image into tokens is not enough; the model must relate those tokens to words. The technique that unlocked this is contrastive learning, best known from CLIP.

Contrastive image-text training Take a batch of N (image, caption) pairs scraped from the web. Encode each image with a vision encoder → N image vectors. Encode each caption with a text encoder → N text vectors. Compute all N×N similarities between them, then train so that: matching pairs (image i, caption i) → high similarity non-matching pairs (image i, caption j) → low similarity The result is a shared embedding space in which the vector for a photograph of a dog sits near the vector for the words "a dog". This is what makes zero-shot classification work: to ask "is this a cat or a dog?", embed both phrases and see which is closer. No classifier was trained for that question — and it is also the mechanism that lets text steer an image generator.

Diffusion: Generating by Removing Noise

In plain terms

To make an image, start with pure static and repeatedly ask a neural network: "if this were a slightly noisy picture of a fox in a forest, what would the noise be?" Subtract the predicted noise, and repeat. After twenty or fifty rounds, a fox emerges. The strange part is that this works — and the reason it works is that removing a little noise is a far easier problem than drawing a picture.

Diffusion inverts a process that is trivial to run forwards. Destroying an image is easy: add Gaussian noise repeatedly until nothing remains. That gives you unlimited training data for free — you know exactly what noise you added at every step. Training a network to predict that noise is ordinary supervised learning. And a network that can predict noise can be run in reverse to generate.

Training a diffusion model — the whole loop for each training image x₀: t ~ Uniform(1, T) pick a random noise level ε ~ 𝒩(0, I) sample actual Gaussian noise xₜ = √(ᾱₜ)·x₀ + √(1−ᾱₜ)·ε jump straight to step t — no iteration ε̂ = model(xₜ, t, text_embedding) loss = ‖ε − ε̂‖² plain mean squared error That is the entire objective. Predict the noise. The remarkable result is that a network good at this task is implicitly a model of the whole data distribution, and running it in reverse samples from it. Note the third line: because the forward process has a closed form, you can generate a training example at any noise level in one step. No sequential simulation is needed during training.

The Refinements That Made It Practical

TechniqueProblem it solvesHow
Latent diffusionDiffusing over raw pixels is ruinously expensiveCompress the image ~8× per side with an autoencoder and diffuse in that latent space. Roughly 64× less computation, with little perceptual loss. This is what made high-resolution generation affordable
Classifier-free guidanceOutputs only loosely follow the promptAt each step predict noise both with and without the text, then extrapolate away from the unconditional prediction. One knob trades prompt adherence against diversity — turn it too high and images become oversaturated and stereotyped
Better samplers1,000 sequential network evaluations per imageTreat the reverse process as an ordinary differential equation and use a good solver. 20–50 steps for comparable quality
DistillationEven 20 steps is slow for interactive useTrain a student to reproduce many teacher steps at once. One to four steps, with some quality cost
Diffusion transformers (DiT)Convolutional U-Nets do not scale as predictablyReplace the U-Net backbone with a transformer over latent patches. Scales with the same reliability as language models, which is why current large image and video models use it
Flow matchingDiffusion's noise schedule is fiddly and indirectLearn a velocity field that transports noise to data along near-straight paths. Simpler objective, faster sampling, better behaved. The mainstream successor to classical diffusion formulations
Why diffusion for pixels but autoregression for text Text is discrete, ordered, and causally structured: word n genuinely depends on words 1…n−1, so predicting left to right matches the data. Images are continuous and have no natural ordering — the bottom-right pixel is not "after" the top-left one. Diffusion generates the whole image at once and refines it globally, which suits that structure. The boundary is blurring: autoregressive image models are competitive, particularly inside multimodal models that already generate token sequences, and diffusion language models are an active research direction. Modality does not strictly determine method; it just makes one method a lot more natural.

Video: Adding Time

Video is the hardest generative modality, and the difficulty is not merely that there are more pixels. Three problems compound:

  • Temporal consistency. An object must remain the same object across frames — same identity, same colour, same number of fingers. Generating frames independently produces flickering nonsense.
  • Implicit physics. Convincing video requires objects to fall, liquids to pour, and shadows to move correctly. Nobody trains this explicitly; it must emerge from the data, and its failures are exactly where generated video still looks wrong.
  • Cost. A five-second clip at 24 frames per second is 120 images that must be generated jointly. Attention over spacetime patches is expensive in both compute and memory.

The dominant approach applies the same recipe with a wider definition of "patch": compress video with a spatiotemporal autoencoder, cut the result into spacetime patches spanning several frames, and run a diffusion transformer over the whole sequence. Because the sequence is variable-length, one model can handle different durations, resolutions and aspect ratios — a genuine practical advantage over earlier architectures that fixed all three.

What generated video is actually good at, and what it is not Camera motion, texture, lighting and short human actions are frequently excellent. The reliable failure modes are revealing: object permanence across occlusion (something passes behind a pillar and comes out changed), causal consequence (a glass breaks but the liquid does not spill correctly), counting and text rendering, and long-range narrative consistency. These are not polish problems. They are the signature of a system that has learned the appearance of physics from video without a persistent representation of objects and their state — which is precisely the gap that world-model research is trying to close.

Audio and Speech

Audio splits into two problems with different solutions.

Understanding audio

Convert the waveform to a mel-spectrogram — a time–frequency image — and run an encoder-decoder transformer over it. Trained on very large weakly-labelled multilingual corpora, this yields robust speech recognition and translation that works across accents and noise without task-specific tuning.

Generating audio

A neural codec compresses the waveform into a sequence of discrete codes at a low rate. A transformer then predicts those codes exactly as it would predict words, and the codec decodes them back into sound. Speech becomes a token-prediction problem.

Neural audio codecs are the key enabling technology, and they are worth understanding. Raw audio at 24 kHz is 24,000 samples per second — hopeless for a transformer. A learned codec compresses it to a few hundred discrete tokens per second while retaining enough information to reconstruct intelligible, natural speech. That compression ratio is what brings audio into the same regime as text.

The consequential shift has been speech-to-speech models. The traditional pipeline — transcribe, feed text to a language model, synthesise a reply — discards tone, emotion, emphasis and timing at the first step, and accumulates latency at every stage. A model operating directly on audio tokens keeps all of it and responds fast enough to interrupt and be interrupted, which is what makes a conversation feel like one rather than like a walkie-talkie.

Native Multimodal Models

Early multimodal systems bolted a vision encoder onto a finished language model with a small adapter between them. It worked, and the seams showed: visual reasoning was noticeably weaker than textual reasoning, and the model could describe an image better than it could reason about one.

Current frontier models are natively multimodal — trained from the beginning on interleaved text, images, audio and video in a single transformer, with no bolted-on encoder. The differences that follow are substantive rather than cosmetic:

  • Genuine cross-modal reasoning. Reading a chart and reasoning about its implications, rather than captioning it. Debugging a screenshot of an error. Following a diagram in a document.
  • Interleaved input and output. A conversation can mix text, images and audio freely in both directions.
  • Transfer across modalities. Concepts learned in text inform visual understanding and vice versa, because they share representations rather than merely exchanging messages.
  • Context implications. Images are expensive in tokens — a high-resolution image can cost as much as several pages of text. Video is dramatically worse. This is a real budget constraint, not a footnote, and it shapes what is affordable to build.
The connection to agents and robots Native multimodality is what makes an agent able to operate a computer by looking at the screen (see Agentic AI) and what makes a robot able to follow a spoken instruction about an object it can see (see AI & Robotics). In both cases the model is doing the same thing: taking pixels and language into a shared representation and emitting actions. The vision-language-action models that control robots are, architecturally, multimodal models with an unusual output vocabulary.

World Models

In plain terms

A world model is a neural network that answers "what happens next?" Given the current state and a proposed action, it predicts the resulting state. That lets a system plan by imagining consequences instead of trying them — which is exactly what you want when trying things is slow, expensive, or dangerous.

The idea is old in reinforcement learning: an agent with a learned model of its environment can search over imagined futures rather than acting in the real one. What is new is that video generation models have turned out to be surprisingly capable world models, because generating physically plausible video requires implicitly modelling how the world behaves. Train hard enough on prediction, and physics appears as a side effect.

Where this matters:

  • Robotics. Plan a manipulation by imagining outcomes; generate synthetic training data in imagined environments; evaluate a policy without a physical robot.
  • Interactive environments. Playable worlds generated frame by frame in response to controller input, with no explicit game engine — a striking demonstration that state can be maintained implicitly.
  • Autonomous vehicles. Simulating rare and dangerous scenarios that cannot ethically be collected on public roads.
  • Reasoning about the physical world. Answering "will this stack of boxes fall over?" by prediction rather than by pattern-matching text.
The honest limitation Video models produce sequences that look physical without any guarantee of being physical. They have no explicit state, no conservation laws, no object registry — and they drift over long horizons, gradually violating constraints they appeared to respect at the start. For entertainment this is a quality issue. For a robot planning a real action, or a vehicle predicting a real trajectory, it is a safety issue. Whether learned world models can reach the accuracy that physical control demands, or whether they need explicit structure bolted on, is one of the genuinely open questions in AI right now — and the answer will shape how fast robotics moves.

Check yourself

Why is diffusion training data effectively free, when the model is learning to generate images?

Because the forward noising process is a fixed formula you control. Take any image, pick a random noise level, add exactly that much noise, and you have a labelled example: the input is the noisy image and the target is the noise you added. No human labelling is involved.

Why does latent diffusion cut cost by roughly 64× rather than 8×?

The autoencoder compresses by about 8× in each spatial dimension, so the area — the number of positions the model must process — falls by roughly 8², or 64×.

Why does a generated video get object permanence wrong when it gets lighting right?

Lighting and texture are local, frame-adjacent statistics the model sees constantly. Object permanence requires maintaining a persistent representation of an object through occlusion — state the architecture does not explicitly keep. It has learned the appearance of the world, not a model of the things in it.

Key takeaways

  • Every modality becomes a sequence of vectors — image patches, spacetime patches, audio codec tokens — after which the same transformer machinery applies.
  • Contrastive image-text training builds a shared embedding space, which is what lets text steer image generation and enables zero-shot visual classification.
  • Diffusion learns to predict the noise added by a fixed forward process; running that prediction in reverse generates samples. Training data is free by construction.
  • Latent diffusion, classifier-free guidance, better ODE samplers, transformer backbones and flow matching are the refinements that made it practical.
  • Video is hard because of temporal consistency, implicit physics and joint generation cost — and its failure modes reveal what the model has not represented.
  • World models let systems plan by prediction, but they look physical without being physical, which is fine for media and a genuine problem for control.
